- «Глава 1. Состав библиотеки»: базовая функциональность, контактная информация, печать, варианты отчетов и другие независимые и интегрируемые механизмы.
- «Глава 2. Инструкция по внедрению библиотеки»: выбор по зависимостям, сравнение и объединение, порядок первого внедрения.

- Поставка `ssl_3_1_10.cf`: фактическая версия по метаданным **3.1.10.441**. SHA-256 – `73D50A3390BC7F3B8C482A06D1CC4B11A51398BBAA928B2B993CE08496B440FB`.

Поставку загрузили в отдельную учебную базу и выгрузили ее метаданные. В ветке «Стандартные подсистемы → Базовая функциональность» подтверждено наличие общего модуля `ОбщегоНазначенияКлиентСервер`, в котором есть экспортная процедура `СообщитьПользователю`. Исходная процедура использует встроенные средства платформы – `СообщениеПользователю`, `XMLТипЗнч`, строковые функции и условную компиляцию. В ее теле отсутствуют обращения к другим объектам метаданных БСП. Источник и назначение проверены также по [рекомендации 1С об ограничении использования метода «Сообщить»](https://its.1c.ru/db/content/v8std/src/1%C2%A0200/900/i8100418.htm).

## 1. Сообщение пользователю

```bsl
Процедура СообщитьПользователю(
    Знач ТекстСообщенияПользователю,
    Знач КлючДанных = Неопределено,
    Знач Поле = "",
    Знач ПутьКДанным = "",
    Отказ = Ложь) Экспорт
```

| Параметр | Назначение |
| --- | --- |
| ТекстСообщенияПользователю | Текст сообщения в управляемом интерфейсе |
| КлючДанных | Объект или ссылка, к которым относится сообщение, либо Неопределено |
| Поле | Имя поля, в том числе путь к колонке строки табличной части |
| ПутьКДанным | Путь к реквизиту формы, если он передается отдельно. В вызовах с объектом пропускается |
| Отказ | Выходной флаг. Процедура устанавливает значение Истина |

Использована экспортная процедура с исходным телом из поставки в модуле с исходным именем. В учебной конфигурации включен минимальный состав – метаданные общего модуля и эта процедура. Модуль сохранен в `src/CommonModules/ОбщегоНазначенияКлиентСервер`. Состав модуля сокращен, правообладатель и лицензия сохранены в заголовке, тело процедуры сверено с поставкой. Платформенные зависимости подтверждены при компиляции и исполнении на 1С 8.3.27.1508.

### Места вызова и проверка

- `СпортивныеПравила.ОшибкаПроверки` передает в БСП текст, объект, поле и флаг отказа. Используется при проверках мероприятий, регистраций и протоколов. Пример: площадка «Зал единоборств» занята «Кубком „Олимпа“ по армрестлингу». При попытке проведения пересекающегося мероприятия процедура публикует сообщение и устанавливает отказ.
- В форме протокола процедура также вызывается из команд **Рассчитать места** и **Заполнить участниками** без выбранного мероприятия. Передаются текст, пустой ключ и путь `Объект.Мероприятие`.
- В расширении форма «Учет явки участников» вызывает эту же процедуру, когда пользователь нажимает «Заполнить участниками» до выбора проведенного действующего мероприятия или выбирает мероприятие без регистраций. При проверке проведения документа используется общий вызов из прикладных правил.
- Сценарий 11 получает сообщение через `ПолучитьСообщенияПользователю` и проверяет фразу «Площадка занята». В пользовательском режиме сообщение подтверждено в панели формы на [снимке проверки бронирования](../Проверки/Скриншоты/02%20Конфликт%20бронирования.png).

## 2. Подстановка именованных параметров

В модуле `СтроковыеФункцииКлиентСервер` из той же группы «Базовая функциональность» используется оригинальная функция `ВставитьПараметрыВСтроку(Знач ШаблонСтроки, Знач Параметры)`. Первый параметр – текст с именами в квадратных скобках. Второй – структура с именами и значениями для подстановки. Функция возвращает строку. Тело использует встроенную функцию `СтрЗаменить` и обход структуры. Вызовы других объектов БСП отсутствуют.

В менеджере документа «Мероприятие» функция формирует представление ссылки по шаблону `[Название] ([Когда])`. Например, в протоколе видно «Кубок „Рубежа“ по прыжкам в длину (14.11.2026 11:00)». По этой подписи можно отличить одноименные мероприятия по дате и времени. В конфигурацию перенесена функция с оригинальным телом и заголовком лицензии CC BY 4.0.

Сценарий 13 проверяет название и время в представлении ссылки, а также корректную подстановку строки со знаком процента. Подпись проверена в тонком клиенте в поле «Мероприятие» и в списке протоколов. Представление также используется в документе учета явки и его отчете. Пример применения двух функций показан в приложении к отчету.

Полную подсистему «Базовая функциональность» не подключали. Для будущего расширения до штатной поставки нужно в помощнике первого внедрения выбранной версии сформировать набор зависимостей, выполнить «Сравнить, объединить с конфигурацией из файла» на копии базы и при объединении заменить оба сокращенных модуля оригинальными из поставки. Затем следует обновить конфигурацию базы, выполнить рекомендации помощника по переопределяемым модулям и повторить сценарии 11 и 13. Дублировать общий модуль при таком переносе не нужно.
